# Подготовка к публикации в Google Play

## 0. Сначала: альфа-тест по ссылке

Перед выходом в открытую выдачу лучше запустить **альфа (внутренний) тест** — доступ по ссылке, без модерации карточки в продакшене.

### Вариант A: Внутреннее тестирование (до 100 человек)

1. **Play Console** → приложение → **Тестирование** → **Внутреннее тестирование**.
2. Создать релиз и загрузить AAB (тот же, что собран `eas build --platform android --profile production`).
3. В разделе **Тестировщики** добавить список email (до 100) или создать список и привязать его.
4. Сохранить и запустить релиз.
5. **Скопировать ссылку на участие:** в блоке «Тестировщики» есть ссылка вида `https://play.google.com/apps/internaltest/...` — её даёте тестерам. По ней они нажимают «Участвовать» и получают доступ к установке из Play.

Тестеры должны входить в аккаунт Google с того же email, что добавлен в список.

### Вариант B: Закрытое тестирование (альфа, по ссылке)

1. **Тестирование** → **Закрытое тестирование** → создать трек «Альфа» (если ещё нет).
2. Загрузить AAB в этот трек и отправить на проверку (первый раз модерация быстрая).
3. В **Тестировщики** создать список по email или подключить **Google Group**.
4. После публикации в консоли появится **ссылка для вступления в тестирование** — ею делитесь с тестерами. По ссылке они переходят в Play и становятся тестерами.

Для «доступ только по ссылке» без ручного добавления email удобно использовать **открытое тестирование**: создать трек «Открытое тестирование», загрузить AAB — в консоли будет одна ссылка; любой, кто перейдёт по ней, сможет стать тестером и установить приложение.

### Итог по шагам

1. Собрать AAB: `eas build --platform android --profile production`.
2. В Play Console создать приложение (если ещё нет), заполнить обязательный минимум (страна, политика конфиденциальности, рейтинг контента, Data safety).
3. Выбрать трек: **Внутреннее тестирование** (или Закрытое/Открытое альфа).
4. Загрузить AAB в этот трек и опубликовать.
5. Скопировать ссылку для тестеров и раздать её — доступ по ссылке готов.

После альфы тот же AAB (или новая версия с увеличенным `versionCode`) переносится в Production.

## 1. Сборка (уже настроено)

- **AAB:** в `eas.json` для production указан `buildType: "app-bundle"` — загружать в Play нужно именно AAB.
- **Пакет:** `com.drinknote.app` в `app.json`.
- **Версия:** `version: "1.0.0"`, `android.versionCode: 1` (для следующих релизов увеличивать versionCode).

Сборка релиза:
```bash
eas build --platform android --profile production
```

После сборки скачать AAB из [expo.dev](https://expo.dev) или подставить в submit.

---

## 2. Загрузка в Google Play Console

1. Создать приложение в [Play Console](https://play.google.com/console) (если ещё не создано).
2. **Загрузить AAB:** Релизы → Production (или тестовый трек) → Создать релиз → загрузить AAB.
3. **Подписание:** включить Google Play App Signing (рекомендуется); первый раз загрузить ключ подписи или использовать ключ от EAS.

Отправка через EAS (после настройки credentials):
```bash
eas submit --platform android --profile production --latest
```

---

## 3. Карточка приложения (Store listing)

Заполнить в разделе «Наличие приложения» → «Основные сведения»:

| Поле | Требования |
|------|------------|
| **Название** | до 30 символов |
| **Краткое описание** | до 80 символов |
| **Полное описание** | до 4000 символов |
| **Скриншоты** | минимум 2, лучше 4–8 (телефон); можно добавить планшет |
| **Графический баннер (Feature graphic)** | 1024×500 px |
| **Иконка приложения** | 512×512 px (PNG, 32-bit) |
| **Видео** | по желанию (YouTube) |

Язык: можно добавить русский как основной.

## 4. Контент и конфиденциальность

- **Рейтинг контента:** пройти анкету (обычно для такого приложения — для всех возрастов или 3+).
- **Политика конфиденциальности:** обязательна, если приложение собирает или хранит персональные данные.  
  DrinkNote хранит данные локально (записи, цели, настройки). Если есть экспорт/импорт или облако — указать в политике. Рекомендуется выложить страницу с политикой (сайт/GitHub Pages) и указать URL в консоли.
- **Безопасность данных (Data safety):** в форме указать:
  - данные хранятся только на устройстве (если нет сервера);
  - покупки в приложении обрабатывает Google Play (данные карты не передаются вам);
  - при необходимости: «данные о здоровье» / «другая персональная информация» — только локальное хранение.

---

## 5. Покупки в приложении (In-app purchases)

- В Play Console создать товар (премиум) в разделе «Монетизация» → «Продукты» → «Покупки в приложении».
- ID товара должен совпадать с тем, что используется в коде (проверить в `services/purchases.ts`).
- Для платного приложения или подписок — настроить соответствующие продукты.

---

## 6. Перед первой отправкой на модерацию

- [ ] Собрать production AAB: `eas build --platform android --profile production`
- [ ] Убедиться, что в приложении нет тестовых/отладочных данных по умолчанию
- [ ] Подготовить скриншоты (2–8), иконку 512×512, баннер 1024×500
- [ ] Написать краткое и полное описание, указать политику конфиденциальности (URL)
- [ ] Пройти анкету рейтинга контента и заполнить Data safety
- [ ] При необходимости сжать `assets/icon.png` и `assets/favicon.png` (см. `docs/SIZE_REPORT.md`)
