# Настройка PWA для DrinkNote

## Что такое PWA?

**Progressive Web App (PWA)** — это веб-приложение, которое работает как нативное:
- ✅ Устанавливается на домашний экран
- ✅ Работает офлайн (с Service Worker)
- ✅ Выглядит как нативное приложение
- ✅ Работает на iOS и Android
- ✅ **Не требует маркетплейсов!**

## Преимущества PWA:

1. **Бесплатно** — не нужны аккаунты разработчика
2. **Простое распространение** — просто дайте ссылку на сайт
3. **Кроссплатформенность** — один код для всех платформ
4. **Автоматические обновления** — пользователи всегда получают последнюю версию
5. **Не требует установки** — можно использовать прямо в браузере

## Недостатки PWA:

1. **Ограниченный доступ к нативным API** — некоторые функции недоступны
2. **iOS ограничения** — на iOS PWA работает хуже, чем на Android
3. **Нет push-уведомлений на iOS** (только на Android)
4. **Ограниченный доступ к файловой системе**

## Настройка PWA для Expo:

### 1. Обновите app.json:

```json
{
  "expo": {
    "name": "DrinkNote",
    "slug": "DrinkNote",
    "version": "1.0.0",
    "web": {
      "favicon": "./assets/favicon.png",
      "name": "DrinkNote",
      "shortName": "DrinkNote",
      "lang": "ru",
      "scope": "/",
      "themeColor": "#6366f1",
      "backgroundColor": "#000000",
      "display": "standalone",
      "orientation": "portrait",
      "startUrl": "/",
      "bundler": "metro"
    }
  }
}
```

### 2. Установите необходимые пакеты:

```bash
npx expo install expo-web-browser
```

### 3. Запустите веб-версию:

```bash
npm run web
```

### 4. Проверьте PWA:

1. Откройте в браузере: `http://localhost:8081`
2. В Chrome DevTools → Application → Manifest — проверьте манифест
3. В Chrome DevTools → Application → Service Workers — проверьте Service Worker

### 5. Соберите для продакшена:

```bash
npx expo export:web
```

Это создаст папку `web-build` с готовым PWA.

## Развертывание PWA:

### Вариант 1: Статический хостинг (рекомендуется)

1. **Netlify** (бесплатно):
   ```bash
   npm install -g netlify-cli
   netlify deploy --dir=web-build
   ```

2. **Vercel** (бесплатно):
   ```bash
   npm install -g vercel
   vercel --prod web-build
   ```

3. **GitHub Pages** (бесплатно):
   - Загрузите `web-build` в репозиторий
   - Включите GitHub Pages в настройках

4. **Свой сервер**:
   - Загрузите `web-build` на любой веб-сервер
   - Убедитесь, что сервер поддерживает HTTPS (обязательно для PWA)

### Вариант 2: Облачные платформы

- **Firebase Hosting** (бесплатно)
- **AWS S3 + CloudFront**
- **Azure Static Web Apps**

## Что нужно проверить:

### ✅ HTTPS обязателен
PWA работает только через HTTPS (или localhost для разработки)

### ✅ Манифест настроен
Проверьте `web-build/manifest.json`

### ✅ Service Worker работает
Проверьте офлайн-режим в DevTools

### ✅ Иконки настроены
Убедитесь, что все размеры иконок присутствуют

## Ограничения для вашего приложения:

### Что может не работать в PWA:

1. **expo-document-picker** — выбор файлов работает, но ограниченно
2. **Некоторые нативные API** — могут требовать полифиллов
3. **Push-уведомления на iOS** — не поддерживаются
4. **Фоновая синхронизация** — ограничена

### Что будет работать:

✅ Все основные функции приложения
✅ AsyncStorage (работает через localStorage)
✅ Календарь и статистика
✅ Импорт/экспорт данных
✅ Темная тема

## Тестирование PWA:

1. **Chrome DevTools**:
   - Application → Manifest
   - Application → Service Workers
   - Lighthouse → PWA аудит

2. **Мобильные устройства**:
   - Откройте сайт в браузере
   - Добавьте на домашний экран
   - Проверьте работу офлайн

## Рекомендации:

Для DrinkNote PWA — **отличный вариант**, потому что:
- Приложение не требует сложных нативных API
- Данные хранятся локально (AsyncStorage)
- Не нужны push-уведомления
- Простое распространение через ссылку

**Идеальный вариант:** Сделайте и PWA, и нативные версии:
- PWA для быстрого распространения
- APK/IPA для пользователей, которые хотят "настоящее" приложение
